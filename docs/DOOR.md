# Дверь приложения: договор

Ответ чата Аи чату приложения на сообщение 55 владельца (22.11.2026). Сборка Аи **0.54.0**; раздел 9 и
образец посредника переписаны в **0.54.1** (договор не менялся).

Чат приложения показал опытом, что сердце отвечает на `{ do: "look" }` и вне Telegram —
через management `/run` — прежней комнатой владельца (`owner: true`, `first: false`). Но
токен публикации для приложения слишком силён. Здесь — узкая постоянная дверь вместо него:
какой транспорт выбран и почему, точный договор и что уже сделано на стороне сердца.

**Коротко.** Посредник приложения пишет подписанный запрос постом в закрытый канал —
*своим* ботом, не ботом Аи. Сердце получает пост как обычное обновление Telegram, проверяет
подпись, время, повтор, частоту и права и зовёт ту же `onRoom`. Ответ уходит постом в тот же
канал, тоже подписанный. База та же, договор ответа тот же. Ни токена публикации, ни ключа
бота Аи посреднику не нужно; в APK нет ничего, кроме его собственного входа к посреднику.

**Что сделано, а что нет.** Сторона сердца написана и проверена тестами
(`tgcloud/lib/bridge.js`, `createDoor`; `tests/door.test.mjs`). Вживую дверь **не
опробована**: в песочнице чата нет выхода к Telegram, а первая попытка владельца (22.11.2026)
встала на настройке — раздел 9. Дверь закрыта, пока владелец не положит на телефон ключ. Посредника и вход по OIDC пишет чат приложения.

## 1. Почему канал

На платформе код сердца запускают только три вещи (справочник из `@tgcloud/cli` 0.2.0,
`templates/docs/tgcloud-sdk.md`):

1. **обновление Telegram боту** — `tgcloud/handlers/<вид обновления>.js`;
2. **функция мини-приложения** — `POST /api/<имя>`, и только с данными входа Telegram:
   «a call without valid init data gets 401 and the endpoint never runs»;
3. **management `/run`** — с токеном публикации; он же принимает любой код.

Входящего HTTP «просто так», расписания и переменных окружения нет. Значит, узкая дверь —
это обновление Telegram, которое может вызвать посредник.

| Транспорт | Что пришлось бы дать посреднику | Плюсы | Минусы | Итог |
|---|---|---|---|---|
| **Подписанный пост в закрытый канал** | токен *своего* бота и ключ двери | наружу не уходит ничего сильного; все части уже работают у Аи вживую (раздел 10); та же `onRoom`, та же база | 1–3 секунды на запрос; около 20 постов в минуту на бота; ответ длиннее 4096 знаков — частями | **принят** |
| Функция `/api/room` с данными входа, собранными посредником | токен бота Аи: им подписываются данные входа | прямой HTTP, быстро; сердце менять не надо | токен бота — это весь бот: читать и писать от её имени; и не проверено, что платформа такие данные примет | отклонён |
| Management `/run` | токен публикации | опробован чатом приложения | токен публикации — это любой код в её базе | отклонён |
| Сердце само ходит к посреднику за запросами | ничего | второй бот не нужен | сердце просыпается раз в минуту: для комнаты медленно | отклонён |
| Свой вход сердца на своём сервере | всё | свобода | переезд и вторая база — «пока не делать» | отложен |

## 2. Кто есть кто

```
APK ──(вход по OIDC, своя сессия)──▶ посредник ──(бот двери)──▶ канал двери ──▶ Аи: onRoom
APK ◀──────────────────────────────  посредник ◀──────────────  канал двери ◀──  Аи: ответ
```

| Кто | Что хранит | Чего у него нет |
|---|---|---|
| **APK** | свою сессию у посредника | ключа двери, токенов ботов, токена публикации |
| **Посредник** (сервер чата приложения) | токен бота двери; ключ двери | токена бота Аи, токена публикации, базы |
| **Бот двери** | свой бот от @BotFather — не Аи и не бот, занятый другой программой; администратор канала двери. Слушает его кто-то один: посредник (вебхуком или `getUpdates`) либо телефон владельца на время опыта | — |
| **Канал двери** | закрытый канал: владелец, Аи и бот двери. Подписчиков нет. **Отдельный**: канал моста и будильника (`ABILITIES_CHANNEL_ID`, `ALARM_CHAT_ID`) дверью быть не может — дверь забирает себе все посты своего канала. Посредник такой канал не принимает, сердце с таким ключом дверь не открывает («закрыта — канал двери тот же, что у моста») | — |
| **Телефон владельца** | ключ двери — строкой `KEY_DOOR` в `~/.heart.env`, как прочие ключи | — |
| **Сердце** | ключ двери — в опубликованном коде: вписывается при публикации (`lib/secrets.js`), в репозиторий не попадает | — |
| **Репозиторий** | ничего: он открытый | ключа двери |

**Ключ двери** — одна строка `KEY_DOOR=<номер канала>:<секрет>`: номер начинается с
`-100`, секрет — от 32 печатных знаков ASCII. Секрет без канала ничего не открывает: запрос
с верной подписью из другого канала сердце не увидит. Ключ HMAC — байты строки секрета как
есть (не раскодированный base64).

**Кто вошёл** — числовой Telegram ID (`uid`), тот же, что `ctx.initData.user.id` у
страницы. Его называет посредник после проверки входа; сердце токен входа не видит и
посреднику верит. Поэтому **пока дверь пускает только владельца** (`OWNER_TG_ID`): чужой
`uid` получает отказ `door_closed`. Гостям дверь открывает строка `DOOR_GUESTS: true` в
`tgcloud/lib/config.js` — по слову владельца.

## 3. Запрос

Пост в канал двери, текст целиком:

```
AI-DOOR1 {"v":1,"t":"q","id":"q7Hk2mZx9LpA","ts":1795338000123,"uid":123456789,"do":"feed","in":"{\"id\":\"abc123\"}","sig":"3659155c…"}
```

После `AI-DOOR1` и пробела — один объект JSON. Без `parse_mode`. Правка поста запросом не
считается.

| Поле | Вид | Что это |
|---|---|---|
| `v` | число `1` | версия договора |
| `t` | `"q"` | запрос |
| `id` | строка, 8–40 знаков из `A-Z a-z 0-9 _ -` | одноразовый номер запроса; случайный, не меньше 64 бит |
| `ts` | целое, миллисекунды Unix | время посредника |
| `uid` | целое больше нуля | Telegram ID вошедшего |
| `do` | строка, 1–16 строчных латинских букв | действие комнаты (раздел 6) |
| `in` | строка до 1024 знаков или нет поля | **JSON-объект с полями действия, записанный строкой**; нет поля — `{}` |
| `sig` | 64 шестнадцатеричных знака, строчные | подпись |

**Подпись.** `sig = hex(HMAC-SHA256(секрет, строка))`, где строка — поля через перевод
строки (`\n`, один байт `0x0A`), в UTF-8, без перевода строки в конце:

```
AI-DOOR1
q
<id>
<ts десятичной записью>
<uid десятичной записью>
<do>
<in — ровно та строка, что в поле; нет поля — пусто>
```

Подписывается не JSON, а строка: «канонического вида» нет, и на любом языке она получается
одинаковой. Поле `in` потому и строка: посредник подписывает и шлёт одни и те же байты.
Другие поля в конверте допустимы, но под подпись не попадают — сердце их не читает.

## 4. Что проверяет сердце

По порядку; первый несошедшийся пункт решает.

| № | Проверка | Не сошлось |
|---|---|---|
| 1 | пост пришёл из канала двери и начинается с `AI-DOOR1` | не её дело: молчит |
| 2 | после метки читается объект JSON | пометка `bad_envelope` |
| — | `t` равно `"q"` (ответы и пометки в канале — не ей) | молчит |
| 3 | поля нужного вида (раздел 3) | пометка `bad_envelope` |
| 4 | подпись верна | пометка `bad_signature`; владельцу — весть, раз в сутки |
| 5 | `ts` расходится с временем поста (`date`, ставит Telegram) не больше чем на 120 с | пометка `stale` |
| 6 | пост не старше 10 минут по часам сердца | молчит: ответа уже никто не ждёт |
| 7 | дверь целиком: меньше 18 постов сердца в канал за эту минуту | молчит |
| 8 | человек: меньше 10 запросов за эту минуту | ответ `slow` |
| 9 | `id` раньше не встречался (память — сутки) | молчит |
| 10 | `uid` — владелец (или дверь открыта гостям) | ответ `door_closed` |
| 11 | `do` — в списке разрешённых | ответ `forbidden` |
| 12 | `in` — JSON-объект | ответ `bad_input` |
| — | `onRoom({ ...in, do }, { initData: { user: { id: uid } } })` | ответ комнаты |

**Про время.** Часам платформы верить нельзя: у разных запусков они расходились на
2,5–3,5 минуты (журнал Аи, 15.11.2026). Поэтому свежесть меряется временем поста, которое
ставит Telegram, — одним для обеих сторон. Часы посредника должны идти верно (NTP).
Чужой, кто перепишет пойманный конверт новым постом, получит новое время поста и старое
`ts` — пункт 5 его не пустит и через сутки, когда номер забудется.

**Про повтор.** Конверт не шлют дважды. Ответа нет — новый конверт: новый `id`, новое `ts`.
Чтобы действие не выполнилось дважды, внутри `in` остаётся тот же номер действия (`in.id`,
раздел 6): комната второй раз ничего не меняет и отвечает тем, что есть.

## 5. Ответ

Один или несколько постов в тот же канал. Каждый — часть:

```
AI-DOOR1 {"v":1,"t":"a","re":"q7Hk2mZx9LpA","n":1,"of":1,"ts":1795338001456,"body":"{\"ok\":true,…}","sig":"…"}
```

| Поле | Что это |
|---|---|
| `t` | `"a"` — ответ |
| `re` | `id` запроса |
| `n`, `of` | номер части с единицы и число частей (до 8) |
| `ts` | время сердца, миллисекунды; только для журнала — свежесть по нему не мерить |
| `body` | кусок текста ответа |
| `sig` | подпись части |

Строка под подпись части:

```
AI-DOOR1
a
<re>
<n>
<of>
<ts>
<body — как есть>
```

**Собрать ответ:** взять посты канала с `t: "a"` и своим `re`, проверить подпись каждого,
дождаться всех `of` частей, склеить `body` по порядку `n` и разобрать как JSON. Части с
неверной подписью — выбросить. Получится **ответ `onRoom` без изменений** — тот же объект,
что получает страница: его договор — `LOOK`, `ANSWERS` и `ALBUM_ITEM` в
`tests/sturdy.test.mjs` и раздел 1 в [APP.md](APP.md).

Отказ — тоже ответ, того же вида, что у комнаты: `{ "ok": false, "code": "…", "text": "…",
"build": "…" }`.

| `code` | Чей отказ | Что значит |
|---|---|---|
| `door_closed` | двери | дверь пока пускает только владельца |
| `forbidden` | двери | такого действия через дверь не делают |
| `slow` | двери | больше 10 запросов в минуту; рядом `retry` — через сколько секунд можно |
| `bad_input` | двери | `in` — не JSON-объект |
| `too_big` | двери | ответ не влез в 8 постов |
| `auth`, `off`, `storage`, `closed`, `unknown`, `runtime_error` | комнаты | как у страницы |

**Знаки в посте.** В текст поста идут как есть только латиница с цифрами, кириллица и
`« » — – … №`; всё остальное (эмодзи, неразрывные пробелы, значки) записано как `\uXXXX`.
Разбор JSON возвращает знаки сам — отдельно это раскодировать не нужно. Запросы стоит
писать так же: Telegram в таких знаках ничего не поправит.

**Размеры.** «Зайти» (`look`) — около 2–2,5 тысяч знаков: один пост. Альбом давнего
знакомого — 5–6 тысяч: два поста.

## 6. Действия

Разрешены: `look`, `pet`, `feed`, `play`, `tea`, `water`, `pat`, `book`, `quiet`, `wear`,
`brew`, `call`, `window`, `lamp`, `music`, `pick`, `album`, `gift`, `snap` — всё, что
делает страница, кроме `oops` (журнал ошибок самой страницы). Список — `DOOR_ALLOW` в
`tgcloud/lib/bridge.js`; новое действие комнаты попадает в него только решением чата Аи.

Поля в `in` — те же, что шлёт страница:

| Поле | У каких действий | Что это |
|---|---|---|
| `id` | у всех, что меняют комнату | номер действия, 6–20 знаков из `a-z 0-9`: тот же номер второй раз ничего не меняет |
| `again` | `look` | `true` — человек вернулся на открытую страницу |
| `kind` | `tea`, `brew`, `gift` | какой чай, какой подарок |
| `wear` | `wear` | что надеть |
| `key`, `pick` | `pick` | сценка и выбор в ней |

Внутри комнаты действуют её собственные пределы частоты и правила «раз в день» — как для
страницы.

## 7. Пометка «дверь не пустила»

Когда запрос не разобран, подпись неверна или время не сошлось, сердце ничего не исполняет
и пишет в канал пометку:

```
AI-DOOR1 {"v":1,"t":"e","re":"q7Hk2mZx9LpA","code":"bad_signature","ts":1795338001456,"build":"0.54.0","sig":"…"}
```

Строка под подпись: `AI-DOOR1`, `e`, `<re>`, `<code>`, `<ts>`, `<build>` — через `\n`.
`re` — номер запроса, если он читался, иначе пусто. Коды: `bad_envelope`, `bad_signature`,
`stale`. Пометка — для отладки: не больше трёх за десять минут, дальше молча. Если подпись
пометки у посредника не сходится — у сторон разные ключи; код тогда годится только для
журнала.

## 8. Что должен посредник

1. Проверить вход человека и взять из него числовой Telegram ID. Из какого поля токена — его
   дело.
2. На каждый запрос — новый `id` и текущее `ts`; пост в канал ботом двери.
3. Ждать ответ до 10 секунд. Нет — сказать приложению «нет связи»; повтор — новым конвертом.
4. Проверять подпись каждой части ответа; неподписанному не верить.
5. Держать свой предел: не больше 10 запросов в минуту на человека и 15 на дверь целиком.
   На ответ Telegram `429` — ждать `retry_after`.
6. Убирать прочитанные ответы из канала (`deleteMessage`): канал — провод, а не журнал.
   Запросы убирает сердце.
7. Ключ двери и токен бота не писать в журналы и не отдавать в APK.

Обновления бот двери получает как удобно: вебхуком или `getUpdates` с
`allowed_updates: ["channel_post"]`. **Слушатель у бота один.** Пока у бота вебхук, `getUpdates` отвечает
`409 Conflict`; два `getUpdates` разом сбивают друг друга. Поэтому бот двери — отдельный, ничем другим не
занятый, и когда посредник начнёт его слушать, опыт с телефона тем же ботом перестанет идти — это не поломка.
Образец (`scripts/door-client.mjs`) чужой вебхук не снимает никогда: бот занят — берётся другой.

**Образец.** `scripts/door-client.mjs` — то же на Node без зависимостей: `sealRequest`
запечатывает запрос, `openAnswer` собирает ответ. Он сверен с сердцем тестами; на телефоне
им же делается опыт (раздел 9).

## 9. Как открыть дверь (владелец)

Одной командой на телефоне. Нужен **свой бот двери** — новый, от @BotFather. Бот будильника не годится: он живёт на
сервере (у него вебхук), и с телефона его не спросить — в это упёрся первый опыт 22.11.2026.

**Бот двери один, и это бот самого приложения** (сообщение 58: «придётся ещё ботов создавать? А попроще никак?»). Им
посредник пишет в канал; завести его можно сейчас — для пробы с телефона — или в тот день, когда приложение будет
готово: токен тот же. Если бот для приложения уже есть (например, для входа через Telegram), годится он. Без бота на
этой платформе двери не сделать (раздел 1). **Открывать дверь заранее не обязательно**: Аи, комната в Telegram и
будильник работают без неё.

1. В Telegram у @BotFather: `/newbot`, имя и адрес любые. Он пришлёт токен — скопировать.
2. В Termux остановить дом (Ctrl+C) и выполнить:

```
cd ~/Ai && bash scripts/phone.sh door
```

3. Команда ведёт по шагам и останавливается на том, который не вышел:

| Шаг | Что делает команда | Что делает владелец |
|---|---|---|
| бот двери | проверяет бота: не Аи ли это и нет ли у него вебхука; годного нет — спрашивает токен | вставляет токен (на экране он не показывается) |
| канал | ждёт до десяти минут, пока бот двери станет администратором канала, и ещё до трёх — Аи; проверяет, что канал закрытый, называет права Аи и лишних читателей | создаёт **закрытый канал** — отдельный, не «Мост» (никого не приглашать), делает администраторами **бота двери** и **Аи** — обоим публиковать и удалять сообщения, пишет в канале любое слово |
| ключ | придумывает секрет и дописывает строку `KEY_DOOR` в `~/.heart.env` | — |
| сердце | публикует сердце с ключом — если с этим ключом оно ещё не публиковалось | — |
| опыт | шлёт запрос «зайти» ботом двери — от имени хозяина, записанного в `tgcloud/lib/config.js`, — и ждёт ответ сердца; сразу после публикации при молчании пробует второй раз | — |

Удача — строка «✓ Дверь работает: сердце ответило за … с» и, в «статус» у Аи, «Дверь приложения: открыта только вам ·
за сутки запросов: N». После команды дом запускается сам. Повторять её можно сколько угодно: сделанное она не
переделывает.

Посреднику нужны тот же ключ — строка `KEY_DOOR` из `~/.heart.env` — и токен бота двери (`DOOR_BOT_TOKEN` там же). В
чат их не слать: владелец кладёт их на сервер посредника сам.

**Если опыт без ответа**, команда говорит, лежал ли запрос ещё в канале: «Аи его не прочла» — пост до сердца не дошёл
(Аи не администратор канала или ключ не опубликован); «прочла и убрала, но ответ не дошёл» — сердце ответило, а бот
двери ответа не получил. Вместе со строкой «Дверь приложения» из «статус» это показывает, где искать.

**Закрыть дверь** — убрать строку `KEY_DOOR` и опубликовать заново (`bash scripts/phone.sh deploy`). **Сменить ключ** —
убрать строку и снова `bash scripts/phone.sh door`; новый ключ передать посреднику.

По шагам вручную — тем же файлом: `node scripts/door-client.mjs bot <токен>`, `setup`, `look`; что он умеет — в его
шапке.

## 10. Что проверено

| Что | Как |
|---|---|
| То, что второй бот делает в канале, доходит до сердца обновлением | вживую — для правки поста: минутный будильник, второй бот правит пост в своём канале (`edited_channel_post`). Новый пост второго бота (`channel_post`) идёт тем же путём, но вживую не мерился |
| HMAC-SHA256 на платформе | вживую: тем же `hmac` подписан мост с Юи |
| `setIfAbsent` и база | вживую: на них держится всё сердце |
| Дверь целиком: подпись, время, повтор, частота, права, части, пометки | тесты `tests/door.test.mjs`, на заглушке платформы |
| Образец посредника против сердца | тот же файл: опыт через поддельный Telegram (`tests/fixtures/telegram.mjs`), написанный по исходникам сервера Bot API — вебхук и `409`, список администраторов без чужих ботов, свои посты боту не приходят |
| Команда владельца целиком (`bash scripts/phone.sh door`) | `tests/phone.test.mjs`: настоящий скрипт, посредник и сердце; поддельные — Telegram и платформа. И случай 22.11.2026 — бот с вебхуком |
| Числа из примера ниже | тот же файл: сверены с `node:crypto` |

**Не проверено вживую:** сама дверь на платформе. Первая попытка владельца (22.11.2026) до двери не дошла: для
опыта был взят бот будильника, а у него вебхук. Остаётся неизвестным, что новый пост бота двери
приходит сердцу обновлением `channel_post`; сколько длится запрос; предел в 20 постов
в минуту — число из правил Telegram для ботов, на этом канале не мерилось; что Telegram не
меняет текст постов двери (для того и запись `\uXXXX`).

## 11. Чего в этой версии нет

- **Сердце не проверяет токен входа само.** Кто вошёл, говорит посредник. Следующий шаг,
  если дверь откроют гостям: передавать токен входа в конверте и проверять его подпись в
  сердце — тогда утёкший ключ двери не откроет чужую комнату. Не сделано: вид токена
  Telegram и проверка RSA на платформе не опробованы.
- **Ответ идёт только через канал.** Упрётся дверь в 20 постов в минуту — ответ можно
  отдавать посреднику прямым запросом HTTPS из сердца: без частей и без предела канала.
- **Разговора через дверь нет**: в комнате его пока нет и у страницы (идея 204).
- **Первой Аи через дверь не пишет**: уведомления приложения — отдельный вопрос.
- Второй памяти и переезда нет: один человек — одна Аи.
