# AGENTS.md

Памятка для ИИ-агента (и человека), который открывает этот репозиторий.
Короткая и правдивая; подробности — в файлах, на которые она ссылается.

## Сначала прочитать

1. [docs/JOURNAL.md](docs/JOURNAL.md) — память чата разработки: кто владелец,
   что он решил, что обещано, что не проверено, какие ошибки не повторять.
2. [docs/IDEAS.md](docs/IDEAS.md) — реестр идей с номерами и состоянием.
3. [README.md](README.md) и [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — что
   умеет Аи и как она устроена.

В конце каждого хода — дописать `docs/JOURNAL.md`. Это единственная память,
которая переживает сжатие разговора и новый чат.

## Что это за проект

Telegram-бот **Аи** («сердце») на платформе Telegram Serverless. Код, который
исполняет платформа, лежит в `tgcloud/`; всё остальное — локальное.

| Путь | Что там |
|---|---|
| `tgcloud/handlers/` | обработчики; имя файла — тип обновления Bot API (`message`, `callback_query`, …), один уровень |
| `tgcloud/lib/` | вся логика; главный файл — `heart.js` |
| `tgcloud/lib/data/` | свои данные: города, слова, квиз, истории; `phrases.js` собирается из `PHRASES.txt` — руками не править |
| `tgcloud/lib/config.js` | несекретные настройки; `secrets.js` в git пуст и заполняется при публикации |
| `PHRASES.txt` | словарный запас Аи; после правки — `npm run phrases` |
| `scripts/phone.sh` | «дом» на телефоне владельца: тесты → публикация → будильник |
| `tests/` | тесты на стабе платформы (`tests/fixtures/kit.mjs`) |

## Правила платформы, которые кусаются

- Свои модули импортируются относительным путём **с `.js`**; SDK — по имени:
  `import { db, api, fetch, InputFile } from "sdk"`.
- В рантайме нет ни файловой системы, ни npm-пакетов, ни переменных
  окружения. Секреты попадают в `tgcloud/lib/secrets.js` только на время
  публикации.
- Обработчик получает полезную нагрузку обновления (`Message`,
  `CallbackQuery`), целое обновление — в `ctx.update`.
- Мини-приложение: статическая папка, названная в `tgcloud.jsonc`
  (`"static"`), и функции в `tgcloud/endpoints/<имя>.js`
  (`POST /api/<имя>`, проверенный `ctx.initData.user`). Пока не используется.
- Справочник SDK — в пакете `@tgcloud/cli`
  (`src/templates/docs/tgcloud-sdk.md`).

## Правила работы

- Ветка одна: `arena/95ac5a16-ai` (PR #28). В `main` не сливать, не
  публиковать: публикует телефон владельца, когда меняется `BUILD`.
- Кнопку в GitHub Actions (`heart.yml`: `smoke`, `deploy`, `tick`) самому не
  нажимать: владелец решил обходиться без Actions из-за лимита минут. Нужна —
  сначала спросить.
- Имя нового обработчика (`tgcloud/handlers/…`) должно быть в списке
  платформы. Список получен 14.11.2026 и записан в `docs/IDEAS.md` («События
  платформы»); проверить заново — `bash scripts/phone.sh events` на телефоне.
  К новому обработчику — строка-репетиция в `publish()` (`scripts/phone.sh`).
- `npm run ci` должен быть зелёным; на каждое новое поведение — тест на
  стабе. Тесты не должны зависеть от скорости устройства: они идут на
  телефоне перед публикацией.
- `BUILD` в `tgcloud/lib/heart.js`, версия в `package.json` и строки
  `RELEASE_NOTES` меняются вместе (`tests/audit.test.mjs` это сверяет) — и
  последним коммитом: телефон публикует, как только видит новый `BUILD`.
- Коммит — после зелёных тестов и через `&&`, а не `;`. Тесты — полным
  прогоном (`npm run ci`), а не несколькими файлами.
- **К владельцу нет ограничений** (его решение 15.11.2026): любое правило,
  которое может отказать, промолчать или заставить ждать (тишина, нормы, паузы,
  права админа, выключатели чата), пишется с проверкой `owner(id)` впереди.
  Исключения и их причины — `docs/IDEAS.md`, «Хозяин без ограничений».
- Номера идей идут подряд: отклонённая идея заменяется на своём месте, новые
  номера после неё не заводятся.
- Дословный текст сообщения владельца — в `docs/JOURNAL.md` первым действием
  хода, до работы.
- То, что уходит от будильника (напоминание, открытка, итоги), отмечается
  «сказано» до отправки, через `store.update`: будильник может ударить дважды.
- Удаление по началу ключа (`store.sweep`) — только с разделителем в конце
  начала: «…:-10» подходит и к «…:-100».
- Расчёт намазов (`lib/fajr.js`) после любой правки сверяется с библиотекой
  adhan: `scripts/adhan-compare.mjs` (в шапке — как поставить её во временную
  папку). Метод сверяется целиком — со своими минутами и углом магриба, а не
  «в чистом виде»: первая сверка 0.30.0 так пропустила минуты Диянета.
- Перед выпуском — проверка на необъявленные имена (в проект не ставится):
  `mkdir -p /tmp/lint && cd /tmp/lint && npm install eslint@9 globals`, файл
  настроек с правилами `no-undef`, `no-dupe-keys`, `no-const-assign`,
  `no-redeclare`, затем из корня проекта
  `/tmp/lint/node_modules/.bin/eslint --no-config-lookup -c /tmp/lint/eslint.config.mjs tgcloud scripts tests`.
- Секретарь (`lib/secretary.js`): письма из чатов хозяина — не разговор с
  Аи. Их нельзя отдавать в `onMessage`, модели и источникам; хранить — только
  выдержку и только до конца отлучки. Это условие Telegram (раздел 5.4 условий
  для разработчиков), а не вкус.
- Запись, которую правят события (письма, нажатия), пишется через
  `store.update(ключ, правка)`: правка получает свежее значение и только
  считает новое. «Прочитать в начале обработки и записать в конце» нельзя:
  события приходят разом, и второе затрёт первое. Тест на одновременность
  (`Promise.all`) сначала должен упасть на коде без правки.
- Новое слово-команда: сначала `grep` по `tgcloud/lib/` и `PHRASES.txt` — не
  занято ли оно; потом разбор и «чужие фразы» в тесте (похожие по виду слова,
  которые командой не являются).
- Границы рисования задаёт `refusal(text, { free })` в `lib/draw.js`. `free`
  — только хозяин в личке. Ветка `minor` (откровенное с детьми, насилие)
  действует для всех и не снимается никаким словом.
- Художнику уходит только английское описание, собранное `draw.compose`
  (словарь художника → модель → переводчик). Русский текст в `paint` не
  передаётся; нет перевода — честное «не вышло». Готовое описание в словаре
  (`lib/data/subjects.js`) — без отрицаний: художник рисует и то, что «не надо».
- Перед тем как опираться на модель поставщика — открыть её страницу: там
  бывает дата отключения («Planned Deprecation»). Запасной художник, не
  принявший запрос, отдыхает сам (`heart:draw:spares`); убирать его из списка —
  после живого подтверждения.
- `overQuota(turn)` не проверяет, а отвечает: норма вышла — он уже написал
  человеку и вернул этот ответ. Писать `const capped = await overQuota(turn);
  if (capped) return capped;`.
- Новый ключ с номером чата и хвостом («…:<чат>:<что-то>») — в `CHAT_FAMILIES`
  у `forgetChat`; новый ключ с номером человека — в `wipePerson` («удали всё
  обо мне» должно стирать всё его).
- Слова для словаря подбираются прогоном: список реплик → сердце на стабе →
  что ушло к модели. Слова, зависящие от разговора («почему», «конечно»),
  словарю не отдаются.
- Список умений — документ `SKILLS.txt` в корне (как `PHRASES.txt`); после
  правки — `npm run skills`. Новое умение вписывается туда в той же сборке:
  строка с примером в «ёлочках» и имя разбора в строке «разбор:». Перед
  выпуском в нём ставится «сборка: X.Y.Z». `tests/skills.test.mjs` не пропустит
  выпуск, если номер не тот, если в коде есть `parse…`, не названный в
  документе, или если пример из документа уходит к модели.
- Значения из `tgcloud/lib/config.js` и `PROJECT.md` не печатать и не
  цитировать.
- Владельцу — по-русски, коротко, с честным «проверено тестами / не проверено
  вживую».
