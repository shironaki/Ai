# Аи — сердце

Здесь живёт Аи: характер, память, провайдер и решение, что ответить. Здесь нет
модерации, игр, квестов и профилей — это отдельный бот, её брат/сестра.

| | здесь — сердце | отдельно — возможности |
|---|---|---|
| Что | разговор, память, характер, выбор действия | модерация, игры, квесты, профиль, обращения |
| Решает | что уместно и что стоит попросить | можно ли это сделать в этом чате и этому человеку |
| Без второго | отвечает и помнит | работает сам, но без разговора |

## Запуск локально

```bash
npm ci            # зависимостей нет, но конфигурация проверяется
npm run ci        # синтаксис + тесты, без Telegram и без сети
node --test tests/heart.test.mjs -v
```

Проверить ответ живьём, не отправляя сообщение:

```bash
AI_PROVIDER_KEY=... node -e '
  const { createHeart } = await import("./tgcloud/lib/heart.js");
  const heart = createHeart();
  console.log(await heart.onMessage(
    { chat: { id: 1, type: "private" }, from: { id: 1 }, text: "привет" },
    { testRun: true, env: { AI_PROVIDER_KEY: process.env.AI_PROVIDER_KEY } },
  ));
' --input-type=module
```

## Публикация

Платформа — Telegram Serverless. Токены и ключи сюда не кладутся:

| Что | Где | Имя |
|---|---|---|
| CLI-токен приложения | GitHub → Secrets | `TGCLOUD_HEART_TOKEN` |
| Ключ провайдера | GitHub → Secrets | `AI_PROVIDER_KEY` |
| ID владельца (для отчётов о поломках) | GitHub → Secrets | `OWNER_TG_ID` |
| Токен бота | настройки приложения на платформе | не в этом репозитории |

Workflow **Heart**: обычный push → проверки и прогон обработчика без отправки;
ручной запуск с `mode=deploy` → публикация. Ключ провайдера подставляется в
`tgcloud/lib/secrets.js` только на время публикации и сразу откатывается.

## Два бота

Оба самостоятельны и оба полезнее вместе. Связь — приватный канал, где оба
администраторы, и подписанные конверты `AI-BRIDGE1`. Настройка моста:

```js
// tgcloud/lib/config.js
ABILITIES_CHANNEL_ID: "-100…",
ABILITIES_SECRET: "32+ случайных символа",   // тот же, что у второго бота
```

Пока они пусты, мост закрыт: Аи отвечает и помнит сама, а про возможности не
обещает ничего. Как только открыт — «покажи профиль» уходит сестре, а ответ
подписан и проверяем.

### Если сестры нет в чате

Аи спрашивает у неё каталог умений. Пусто — значит её здесь нет, и Аи говорит
это прямо, вместо выдуманного «сделала»:

```
Профиль умеет Юи, но её нет в этом чате. Администратор может добавить: https://t.me/…
```

Ссылка берётся из `SISTER_BOT_USERNAME`; пока он пуст, ссылки нет — только
правда. Право добавлять бота Аи не предполагает: в группе она называет того,
кто может решить, в личке даёт кнопку.

### События без ввода

Тем же каналом сестра присылает события: новичок, конец партии, напоминание,
новый уровень. Аи реагирует сама — коротко, без обращения к модели:

```
AI-BRIDGE1 {"v":1,"tool":"__event","args":{"kind":"member_joined","chatId":-100…,"name":"Ли"},"sig":"…"}
```

Ограничения записаны в `lib/events.js`: только подписанные конверты, только
известные виды, один ответ на вид в чате не чаще раза в 10 минут и не больше
8 в день. Неизвестный вид молчит — новый тип события в соседнем репозитории не
может начать здесь монолог.

### Если что-то сломалось

Сердце не ждёт `/aidiag`: о поломке оно говорит владельцу само, в личку.

```
🚨 Хозяин, у меня это сломалось
━━━━━━━━━━━━━━━━━━━━
Где: Провайдер модели
Что: нет связи с провайдером
Повтор: 3 раза за сутки
Что делать: Ключ провайдера: /aikey.
Код: provider:provider_network_error
```

Правила в `lib/notices.js`: одна поломка — одно сообщение в сутки, не больше
шести в сутки, повторы числом. Не дошло (Telegram, блокировка, офлайн) —
осталось в очереди и уйдёт со следующим обновлением. В подробности нет ни
текста разговоров, ни ключей: они вырезаются до записи.

Кому писать — GitHub-секрет `OWNER_TG_ID` (числовой ID). Именно секрет, а не
строка в `config.js`: `Ai` — публичный репозиторий, и личный ID в нём ни к чему.
Пусто — отчёты копятся в очереди, но никому не уходят; это видно в `/aidiag`.

`docs/INCIDENTS.md` в репозитории возможностей.
