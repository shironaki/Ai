# Telegram bot

Основной запуск проекта: `run.py`. Он импортирует `main.py` как модуль и запускает единственный экземпляр Dispatcher — это предотвращает дублирование обработчиков.

## Требования

- Python 3.11
- Токен Telegram-бота в переменной окружения `BOT_TOKEN`
- Для нейроответов «Аи»: `GROQ_API_KEY` (секрет окружения); модель настраивается через `AI_MODEL`

## Локальный запуск на Windows

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:BOT_TOKEN = "<токен из BotFather>"
python run.py
```

После успешного подключения в консоли появится сообщение, что бот подключён и ожидает сообщения. Напишите боту в личные сообщения `/start`; список команд открывается через `/help`. В личных сообщениях обычный текст передаётся AI, а команды обрабатываются своими handlers.

## Продолжение работы с телефона через Codespaces

1. Загрузите этот проект в приватный GitHub-репозиторий.
2. В GitHub откройте репозиторий, выберите **Code → Codespaces → Create codespace**. Настройка `.devcontainer` установит Python 3.11 и зависимости.
3. В настройках GitHub Codespaces добавьте секрет с именем `BOT_TOKEN`. Не сохраняйте токен в файлах или коммитах. Перезапустите Codespace после добавления секрета.
4. Для AI добавьте секрет `GROQ_API_KEY` при использовании нейроответов.
5. В TEST/Codespace `BOT_TOKEN` должен быть токен отдельного тестового бота, а не production-бота.
6. Откройте Codespace в мобильном браузере и в терминале выполните `bash start.sh`. Скрипт автоматически использует `BOT_ENV=test` и базу `data/test/`.

## TEST / PROD

Репозиторий один, но runtime-контуры разделены:

- TEST: Codespace + TEST token + `data/test/`.
- PROD: отдельный Linux-хост + PROD token + `/var/lib/ai-bot`.
- Один Telegram-токен нельзя одновременно использовать для TEST и PROD.
- Production не зависит от Codespace.

Production-шаблоны и инструкции находятся в `deploy/PRODUCTION.md` и `deploy/systemd/`.

## AI

В личных сообщениях AI работает в двух режимах: команда `/ai`/`/аи` и обычный естественный текст. Команды бота по-прежнему обрабатываются своими handlers; обычный неизвестный текст в ЛС передаётся AI.

## Данные и дополнительные боты

Основной бот создаёт `users.db` и `chats.db` рядом с исходниками. Эти файлы не входят в исходный код и игнорируются Git.

## Архитектура

- `main.py` — bootstrap, Dispatcher, middleware и запуск.
- `handlers/` — Telegram-команды и callbacks.
- `config/` и `core/` — роли и права доступа.
- `services/` — AI и прикладные сервисы.
- `database/` — новый слой чтения данных и схем.
- `base/` — совместимый слой старой SQLite-модели, который пока сохраняет существующие игровые записи без миграции.

Привилегированные команды скрыты из общего меню Telegram и дополнительно защищены проверками ролей в обработчиках.
